# ДЗ №1 — сравнение прямой генерации и подхода через спецификацию

## О проекте

В работе сравниваются два способа создания автономного мини-трекера учебных задач с помощью одной языковой модели.

1. Прямой подход — модель сразу получает запрос на создание HTML-приложения.
2. Подход через спецификацию — сначала создаются и проверяются документы `proposal`, `spec`, `design` и `tasks`, после чего модель реализует приложение.

В обоих экспериментах использовалась модель GPT-6.1 Sol с уровнем рассуждения Medium.

## Возможности трекера

- добавление учебных задач;
- удаление задач;
- изменение статуса «готово»;
- фильтры «Все», «Активные» и «Готовые»;
- подсчёт общих часов;
- подсчёт выполненных часов;
- расчёт прогресса по часам;
- проверка названия задачи;
- проверка часов в диапазоне от 0.5 до 24 с шагом 0.5;
- обработка пустого списка;
- адаптация под ширину экрана 390 px.

## Запуск

Установка библиотек не требуется.

Для запуска открой один из итоговых файлов в браузере:

- `tracker-v1.html` — исправленная версия прямого подхода;
- `tracker-v2.html` — версия, созданная по спецификации.

Все CSS-стили и JavaScript находятся внутри соответствующего HTML-файла. Подключение к интернету для работы трекера не требуется.

## Основные файлы

- `tracker-v1-initial.html` — первоначальная реализация прямого подхода;
- `tracker-v1.html` — исправленная реализация прямого подхода;
- `tracker-v2-initial.html` — первая реализация по спецификации;
- `tracker-v2.html` — итоговая реализация по спецификации;
- `chat-v1.md` — полный диалог прямого подхода;
- `chat-v2.md` — полный диалог подхода через спецификацию;
- `prompts.txt` — запросы, отправленные модели;
- `report.md` — описание эксперимента, тестов и результатов;
- `proposal.md` — цель и границы проекта;
- `design.md` — структура данных и расчёты;
- `tasks.md` — план реализации и проверок;
- `specs/tracker/spec.md` — итоговые требования и сценарии;
- `manual-checks-v2.rtf` — список ручных проверок второй версии.
